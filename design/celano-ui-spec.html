UI SYSTEM REDESIGN / CELANO PPT

把「AI 生成」的不确定性，
收进一套确定、可预期的界面里。

本方案针对现有 CELANO PPT（智绘演示文稿生成系统）重建整套界面体系。产品能力已经完整——主题成稿、2K/4K 原生画面、模版深度参考、多线程并发生图、无限画布、点数计费与后台运营——但界面层仍停留在复刻式的黑白皮肤：只有两三级灰阶、层级全靠阴影、主行动与次要行动无法区分、生成状态只能靠文字辨认、点数消耗藏在弹窗里、对比度多处不足 4.5:1。 方案以黑白为骨、彩色为标点：14 级中性阶建立层级，「强调阶梯」用填充度表达主次，「状态形态语言」用边框样式表达状态，再引入唯一一个低饱和品牌点缀色（澜青·青瓷）——只出现在焦点环、当前项、进度条这些"交互状态"上，主行动永远保持黑白反转。最后配一套 12 条的动效语汇库：黑白界面里，动效与那 5% 的彩色，共同承担了高级感。

01

目标用户群体与核心使用场景

这个产品的用户不是设计师，而是"临时要交一份好看材料"的人。他们的共同特征是：时间压力大、没有排版能力、对结果有审美要求但没有审美自信。因此界面的核心任务不是"提供强大工具"，而是"降低不确定感"——让用户在生成前知道要花多少、生成中知道在做什么、生成后知道能改哪里。

三类主要用户

A职场汇报者 · 高频主力

画像：市场／运营／销售岗，25–40 岁，非设计背景，每周 1–2 次汇报。
任务：用一句话主题，在 2 小时内交出能过审的季度复盘／竞品分析／方案提案。
真实痛点：不会排版；模版库要么土要么贵；"改一页要重来一遍"；不知道这次生成要烧掉多少点。
界面诉求：极短路径进入生成、成本前置可见、单页可局部重做、导出后能在 PowerPoint 里继续改。

B创业者 / 商务拓展 · 质量优先

画像：创始人、BD、咨询顾问，需要对外交付品牌级材料。
任务：打磨一份 20 页路演 BP，反复迭代同一套视觉语言。
真实痛点：品牌一致性难保证（Logo 位置、配色、字重每页都不同）；想换风格只能整篇重来；多版本管理混乱。
界面诉求：全局视觉方向锁定、Logo 与配色的统一控制、批量重生成、版本与导出记录。

C内容 / 教育生产者 · 批量为王

画像：讲师、自媒体运营、培训机构教研。
任务：把一套内容拆成课件 + 社媒配图 + 长图，批量产出。
真实痛点：每次都要重新描述风格；出图慢、排队不可见；素材散落在不同页面找不到。
界面诉求：模版复用与"再来一批"、并发生图的进度可视化、素材库与画布打通。

五条必须被满足的用户任务（JTBD）

130 秒内开始一次生成

首页到"点下生成"之间，认知负担必须极低：一个输入框、三个默认值、一个主按钮。

2生成前知道要花多少点

成本不能只出现在确认弹窗里，应在配置区实时联动显示（页数 × 画质单价）。

3生成中知道在做什么、是否卡住

规划 → 渲染 → 完成的三段式进度，加上每页的并发状态，避免"黑盒等待"。

4单页不满意能只重做这一页

这是留存的关键：局部重生成必须比整篇重来更显眼、更容易。

5成品能带品牌标识导出

Logo、配色、16:9 画幅在预览与导出之间必须完全一致（所见即所得）。

⚠ 当前最大的体验缺口

成本确认弹窗、点数余额、生成进度三者分散在不同页面，用户在一次生成中要做 3 次"上下文切换"才能拼出完整信息。

02

交互习惯与通用约定

一个原则：不发明新范式。用户对 PPT 工具和 AI 生成工具的预期已经被 PowerPoint、Figma、Canva、Midjourney 训练完成，界面应当尽量贴合这些既有肌肉记忆，把创新预算花在"AI 生成"这件事本身的表达上。

A. 平台级通用约定

导航与位置感

  • 全局导航固定在顶部，品牌标记始终可点，点击回到首页。
  • 当前所在位置必须有可见的"选中态"，且可被 URL 直接访问（当前 hash 路由需保证刷新与分享不丢状态）。
  • 深层页面（工作台、账户）显示面包屑 + 返回，返回指向逻辑父级而非浏览器历史。
  • 浏览器后退键必须有效——这是用户检查"我刚才那步"的默认动作。

操作与反馈

  • 每个视图只有一个主行动按钮（E4 反转填充：暗色主题白底黑字、浅色主题黑底白字），其余一律降为 E2 描边或 E0 纯文字。
  • 主行动位于内容流右下或表单右下，符合"从左到右、从上到下"的阅读终点。
  • 破坏性操作（删除作品、清空画布、重置配置）→ 二次确认 + 说明后果 + 提供撤销。
  • 任何超过 400ms 的等待都要有反馈：骨架屏 / 进度条 / 按钮内联 loading。
  • Toast 只承载"已完成的轻量结果"，不得承载唯一关键信息，3 秒自动消失且可关闭。

表单与输入

  • 标签在字段上方（不用占位符代替标签）；占位符只做示例。
  • 校验在失焦后触发，不打断输入；错误信息紧贴字段并说明如何修复。
  • Enter 提交单行表单，Esc 取消；多行文本框内 ⌘+Enter 才提交。
  • 长表单分组，每组有标题；不隐藏必填项。

列表与选择

  • 整行可点击，行内操作按钮用图标 + tooltip，避免与行点击冲突。
  • 批量选择用复选框 + 顶部浮动操作条（"已选 3 项 · 重新生成 · 删除"）。
  • 空态必须给出下一步动作，不能只有一句"暂无数据"。

B. 编辑器与画布的专属约定

三栏心智模型

左＝结构（页列表），中＝对象（画布），右＝属性（检查器）。这是 Figma / Keynote 的共同模型，用户无需学习。

选择语义

单击＝选中，双击＝进入编辑，空白处点击＝取消选中，Shift+点击＝多选，拖拽＝排序或移动。

永不丢失工作

编辑即自动保存，顶栏常驻"已保存 / 保存中 / 保存失败"状态；失败时给出重试，而不是静默丢弃。

撤销是安全网

所有破坏性编辑进入撤销栈（⌘Z / ⇧⌘Z），至少保留 20 步；批量重生成视为一步。

消耗类操作前置告知

任何扣点操作（重生成、提升画质、批量导出）在触发点显示单价与总额，二次确认只在总额超过阈值时出现。

等待不阻塞

生图期间界面必须可交互：能切页、能看其他作品、能离开页面（任务在服务端继续）。

04

色彩规范（无彩色体系）

黑白为骨，彩色为标点。整站 95% 以上是黑 / 白 / 灰，只引入一个低饱和品牌点缀色（澜青·青瓷），且严格限定它只能出现在"交互状态"上——焦点环、当前项、进度条、进行中卡片。主行动永远是黑白反转，绝不着色。 为什么要这样分？因为当前的"黑白"之所以显得平，问题不在"没有颜色"，而在只有 2–3 级灰阶、层级全靠阴影——纯黑 #000 打底、深灰 #1c1c1c 做面，中间没有过渡，于是所有卡片都贴在同一个平面上。而反过来，无节制地加彩色又会滑向廉价。 这一节给出 14 级中性阶 + 强调阶梯 + 彩色点缀系统 + 状态形态语言 四件套：层级交给明度，主次交给填充度，当前状态交给那 5% 的彩色，出错交给边框形态。四者职责互不重叠。

三个关键决定： ① 不用纯黑打底——暗色主题底用 N950 #0B0E10 而非 #000。纯黑与深灰面板之间会形成"黑洞"，阴影完全失效，白字也过于刺眼（对比度 21:1，长时间阅读会累）。#0B0E10 保留了"黑"的观感，但留出了层级空间。 ② 灰阶要密——14 级里真正高频使用的大约是 N25 / N50 / N100 / N200 / N400 / N600 / N800 / N900 / N950 这 9 级，足以支撑页面底 / 卡片 / 悬浮层 / 分割线 / 三种文字 / 两种填充。 ③ 带 2% 冷调——所有灰阶偏向青灰（如 N950 的 R11 G14 B16），肉眼几乎察觉不到色相，只感觉到"干净、不脏"。这是黑白体系显得高级的关键细节，纯中性灰（R=G=B）反而容易显得发黄发脏。

4.2 强调阶梯（用填充度替代强调色）

让用户找到"下一步"的第一手段是填充度差异，不是颜色。填充度越高的元素越重要——这套五级阶梯负责"哪里是主行动"。点缀色（见 4.3）只负责"哪里是当前状态"，两者职责不重叠。主行动永远是黑白反转，绝不用彩色。这是一个刻意的选择：一旦主按钮变成彩色，彩色就失去了"点缀"的身份，整站会立刻变得吵。

为什么"反转"是黑白体系里最强的强调

在满屏深灰的界面里，一个白底黑字的按钮，比任何彩色按钮都更醒目——因为它占据了明度光谱的另一端。当前实现把主按钮做成"白底黑字"其实方向是对的，问题在于次要按钮也几乎是白色（rgba(255,255,255,.06) 底 + 白字），两者填充度差距不够，于是强调失效。
解法不是换颜色，而是把其余按钮压低：次要按钮退回 E2 描边、幽灵按钮退回 E0，让 E4 的反转真正"孤零零"地站着。

配合 4.3 的点缀色之后，一个界面里的三级关系就非常清楚了：主行动＝黑白反转（E4）、当前状态＝澜青弱底 + 澜青文字、其余一切＝中性描边与纯文字。三者用三种完全不同的视觉手段，谁也不会被误认成谁。

4.3 彩色点缀系统（黑白做骨，彩色做标点）

纯黑白做久了会有两个问题：焦点态和当前态只能靠明度区分，长时间使用会疲劳；产品缺少一个能被记住的颜色锚点。 解法不是加一套彩色主题，而是引入极少量、低饱和、严格限定职责的点缀色。关键从来不是"选哪个好看的色"，而是给每个颜色分配互不重叠的语境。

为什么是青瓷绿，而不是红 / 金 / 蓝 / 紫

红 / 金 / 蓝 / 紫 为什么都不合适

红在 UI 里天然带"危险"联想，做通用强调会让用户误判；金容易滑向"土豪"，且与点数（钱）的语义混淆；蓝是 AI 产品的重灾区，与"科技蓝"的廉价感绑定；紫同质化最严重，且已经被当前代码里的残留值证明过不合适。

青瓷绿好在哪

① 与品牌名「青澜」同源，不需要额外解释；② 低饱和带灰，天然温润，在黑白底上既有存在感又不抢戏；③ 是"人眼最不容易疲劳"的色相区间之一，适合长时间驻留的编辑器；④ 与朱砂红构成冷暖对比，但两者语境完全隔离，不会打架。

⚠ 一个必须说明的冲突

青瓷绿 #1B7A68 与跌绿 #17864A 色相只差约 22°，在极少数场景（消耗记录里同时有选中行和绿色数值）可能混淆。

4.5 彩色语境隔离与三条禁令

加彩色之后，最容易失控的不是"颜色不好看"，而是"颜色到处跑"。下面三条是硬约束。

禁令一：主行动不得用彩色

主按钮永远保持黑白反转（E4）。一旦主按钮变彩色，彩色就从"标点"变成了"底色"，整站立刻变吵，而且你会需要第二个颜色来区分不同的主按钮——这是滑坡的开始。

禁令二：同一色相不得跨语境

澜青不得用于数据可视化（否则涨跌失去意义），朱砂不得用于普通强调（否则用户无法判断哪里危险），涨跌色不得出现在按钮或标签上。跨语境使用＝语义失效。

禁令三：不做装饰性上色

不给标题染色、不给卡片加彩色顶边、不给图标上色、不做彩色渐变背景。彩色只出现在有信息量的位置：焦点、选中、进度、危险、数值增减。

与 4.4 的关系：颜色是第二编码，不是唯一编码

引入点缀色不会推翻状态形态语言。失败卡片仍然是虚线边框，红色只是加强；当前项仍然是澜青弱底，但它同时也必须是顶栏里唯一带底色的项；生成中仍然是2px 呼吸描边，只是描边用了澜青。
也就是说——把颜色全部去掉，界面依然完全可用。这是判断"颜色是点缀还是依赖"的唯一标准，也是能同时满足 WCAG 1.4.1（不单独依赖颜色传达信息）和"高级感"的做法。

六条搭配法则（怎么加才高级）

1一个主点缀色，其余都是语义色

品牌色只能有一个。出现第二个"品牌色"，用户就无法判断哪个更重要，界面立刻从"克制"滑向"花哨"。语义色（危险、涨跌）不算品牌色，因为它们只在特定语境出现。

2饱和度压在 45–65%，避免荧光感

青瓷色的关键在于"带灰"。纯度越高的颜色越显廉价——荧光绿、亮青、纯品红都是廉价感的来源。判断方法：把颜色截图转成灰度，如果它在中性灰阶里依然"跳"，说明饱和度过高。

3面积 < 5%

彩色是标点符号，不是底色。一个页面里彩色总面积超过 5%，就开始显得吵。具体到元素：焦点环 2px、进度条 6px 高、状态点 7px、当前项弱底——全部是"小尺寸"元素。

4彩色叠加在形态之上，不替代形态

这是可访问性的底线。失败仍然是虚线边框、当前项仍然是唯一带底色的一项、生成中仍然是 2px 加粗描边。颜色只是"加强"，不是"唯一线索"——去掉颜色后界面必须依然完全可用。

5色彩只在"交互与运动"时出现

静止时界面几乎纯黑白；鼠标移入、键盘聚焦、生成进行中才浮现颜色。这叫色彩作为反馈，比色彩作为装饰高级得多——因为它让颜色承载了信息，而不是填满了画面。

6不做装饰性上色

不给标题染色、不给卡片加彩色顶边、不给图标上色、不做彩色渐变。这是最容易"看起来努力但其实廉价"的一类做法。彩色只出现在有信息量的位置。

三个进阶手法

单色 + 透明度阶

同一个 accent 只用四档透明度：8% / 14% / 24% / 100%，而不是四个不同的颜色。这样无论出现在哪里，用户感知到的都是"同一个颜色"，整体感更强。

优先用"线"和"点"，不用"面"

焦点环、1px 描边、4px 圆点、6px 进度条、下划线。避免大色块——色块一出现，气质立刻从"精密工具"变成"消费级应用"。

深色提亮降饱和，浅色加深保饱和

同一个色相在两套主题下取不同阶：深色主题用 #63D6BC（提亮、降饱和，对比度 11:1），浅色主题用 #1B7A68（加深、保饱和，对比度 5.2:1）。因为对比度是相对背景的，一个值不可能同时适配两种底色。

4.8 搭配法则与使用规则

四条硬规则

  • E4 反转全屏只能有一个。每个视图只允许一个反转填充元素（主行动）。出现第二个，强调就失效了。
  • 层级只用明度差表达，不用阴影。暗色主题下阴影几乎不可见——当前皮肤层级混乱的根因就在这。改用 bg-canvas → bg-surface → bg-subtle → bg-raised 的明度递进 + 1px 描边。
  • 状态必须四重编码。明度 + 边框样式 + 图标 + 文案，缺一不可。禁止只靠颜色或只靠文字。
  • 彩色面积 < 5%，且主行动永不着色。澜青只做"当前状态"，朱砂只做"不可逆操作"，涨跌只做"数值"。三者语境隔离，永不并排出现在同一视觉单元里。

⚠ 必须修掉的现状问题

  • 底色用纯黑 #000（index.css 的 html/body），与 #1c1c1f 面板之间只有一档明度，导致卡片"浮在虚空里"、阴影完全失效。
  • 残留紫色硬编码 #8d76ff / #c8b9ff（home.css 的会员按钮与 eyebrow）、焦点色 #b8a1ff，与"纯黑白"的设计声明自相矛盾。
  • 灰阶文字 #676771 在 #111114 底上对比度约 4.0:1，低于 AA 正文要求。
  • 主按钮与次按钮填充度接近（#fff vs rgba(255,255,255,.06)），E4 与 E3 的差距没有拉开。
  • 没有任何"当前状态"的视觉锚点：选中的页、当前导航项、焦点所在，全靠明度微差，长时间使用极易丢失位置感——这正是需要那 5% 点缀色的地方。

行高与字距

  • 行高按用途固定：标题 1.1–1.3，正文 1.6–1.75，说明 1.5。禁止用 normal。

数字与中文混排

  • 所有数字使用 font-variant-numeric: tabular-nums，让点数、页数、像素在列表中纵向对齐。

可读性上限

  • 正文行长控制在 45–75 字符（中文约 22–38 字），超宽时用 max-width: 34em 约束。

  • 中文字体包体积大，不预加载思源宋体全量：仅在首页与空态标题使用，采用 font-display: swap 并配 Songti SC 本地兜底。

层级超过 3 级就会失去意义。任何页面最多出现：页面底 / 卡片 / 悬浮层。

07

动效规范

在无彩色体系里，动效不再是装饰，而是承担了原本由颜色承担的职责：什么变了、哪里是当前焦点、操作有没有生效、系统是不是还活着。它也是"高级感"最直接的来源——同样一个黑白界面，动效做对了就显得精密，做错了就显得廉价。 当前 motion.css 只有少量入场动画，且未处理 prefers-reduced-motion。下面是完整的动效系统，含可点击重播的实况演示。

7.1 三条原则

只回答三个问题

① 元素从哪来（空间连续性）② 什么状态变了（生成进度、选中）③ 操作生效了吗（按下、保存）。回答不了这三个问题的动画，删掉。

幅度要小，时长要准

位移 ≤ 12px，缩放 ≤ 1.04，透明度变化 ≥ 0.15（低于此值肉眼看不见，等于白做）。超过 400ms 的界面动效会开始显得拖沓。

只动 transform 与 opacity

这两个属性走 GPU 合成层，不触发重排。禁止动画 width/height/top/left/box-shadow 的数值部分——那会让 60fps 掉到 30fps。

7.2 时长与曲线 Token

回弹曲线是双刃剑。它只应该在"用户刚做了一个动作、系统要告诉他成功了"时出现（点扣了、保存了、加入了）。用在入场动画上会显得轻浮，用在生成进度上会显得不专业。

7.4 动效语汇库 · 实况演示

下面每张卡片都是一个真实的动效实现，点击卡片可重播；标注「悬停」的用鼠标移入触发。深色舞台就是创作场（首页 / 生成器 / 工作台）的真实底色。

动效的"高级感"从哪来

不是动画多，而是三个一致：同一类元素用同一个时长、同一个曲线、同一个幅度。当下 motion.css 的问题不是动画太少，而是缺少这套统一标准，导致每次新增动画都要重新拍一次脑袋。

光晕跟随要克制

鼠标位置驱动的高光能显著提升"精密感"，但透明度必须压在 6% 以内、半径 ≥ 240px，并且不加过渡（直接跟随，加了过渡反而迟钝）。移动端不启用。

数字滚动是点数产品的专属细节

扣点、充值、进度百分比都应滚动变化而非瞬间跳变。配合 tabular-nums 让数字宽度恒定，避免整行文字左右抖动——这是很多产品忽略但用户能感觉到的地方。

7.6 性能与降级

性能清单

  • 只动画 transform / opacity；需要动颜色时用 background-color 而非 background-image。
  • will-change 只在动画期间添加，animationend 后移除——常驻会创建过多合成层，反而更卡。
  • 长列表（作品库、消耗记录）使用 content-visibility: auto，跳过视口外的渲染。
  • 循环动画在 document.hidden 时暂停（visibilitychange 监听），避免后台标签页持续占用 GPU。
  • 同一帧内不要同时启动超过 8 个独立动画。

⚠ 必须实现的降级

  • @media (prefers-reduced-motion: reduce)：把时长压到 0.01ms，位移与缩放归零，但保留透明度变化与进度反馈——用户需要知道状态变了，只是不需要看到它移动。
  • 无限循环动画（骨架屏、呼吸描边）在该模式下改为静态的中间态，而不是消失——消失会让用户以为卡住了。
  • 低端设备检测（navigator.hardwareConcurrency ≤ 4）时自动关闭光晕跟随与错峰入场。
  • 当前 motion.css 完全没有处理这条系统偏好，属于必须补齐的可访问性缺陷。

核心操作流程

界面的价值在流程里体现，而不在单页里。下面四条流程覆盖了用户 90% 以上的实际操作路径，每一步都标注了用户此刻最想知道的问题与界面对应的解答。

流程 A · 首次生成（主流程）

01进入首页用户想：这个工具能做什么？
界面答：主标题 + 三个能力入口 + 主行动
02点击「开始制作 PPT」无登录拦截，直接进入生成页（未登录在提交时才引导）
03输入主题用户想：我该写多详细？
界面答：占位符给完整示例 + 字数建议
04配置页数与画质用户想：要花多少？
界面答：成本条实时联动，随配置即时变化
05（可选）上传素材参考资料 / 风格参考 / Logo / 模版，芯片化呈现可移除
06点击「生成 · 24 点」消耗 ≥10 点触发确认弹窗：页数 / 画质 / 总额 / 生成后余额
07进入工作台规划 → 渲染，分阶段进度 + 每页状态，等待期间界面可交互
08预览与微调单页重生成 / 调序 / 改 Logo 位置，自动保存
09导出 PPTX进度可见、文件名明确、完成后 Toast + 直达下载

共 9 步，其中 3 步是本次方案新增或重构的关键节点（成本条、分阶段进度、失败退款说明）。目标：从首页到开始生成不超过 5 次点击。

流程 B · 单页不满意 → 局部重做（留存关键路径）

01在页列表选中该页画布切到该页，检查器载入其属性
02编辑提示词检查器内直接改；提供"恢复原始提示词"
03点击「重新生成本页 −3 点」按钮自带价签，小额不弹窗，仅 Toast 告知
04原图保留在历史生成后可"对比 / 回退到上一版"，避免越改越差
05满意后自动保存顶栏"已保存"状态更新，无需手动操作

为什么这条流程最重要

AI 生成的本质是"概率性产出"——再好的模型也会有 1–2 页不理想。如果用户只能整篇重来，那么每一次不满意都意味着"重新花 24 点 + 重新等待 8 页"，用户的直接反应是放弃这个工具。把"局部重做"做成最顺手的一条路径，是产品从"玩具"变成"工具"的分水岭。当前实现虽然有单页重生成能力，但入口在检查器深处且不带价签，实际使用率会很低。

流程 C · 生成失败与点数退回

01某页渲染失败卡片转危险色 + 显示一行原因（如"上游接口超时"）
02自动退回点数状态栏与卡片同时显示"已退回 3 点"，账务透明
03提供两个选择「重试本页」（再扣 3 点）或「跳过，继续导出」
04批量失败时顶部横幅汇总："3 页失败，已退回 9 点 · 全部重试"

⚠ 这是当前实现最需要补齐的一环

产品已经实现了失败退回的后端逻辑（refundedCredits、refundedSlideIds），但界面上几乎没有表达。用户看到"生成失败"时的第一反应是"我的点被吞了"，而不是"系统会退给我"。把已有的退款能力显性化，是零成本提升信任度的改动。

流程 D · 新用户首启（前 60 秒）

01落地首页不弹注册墙，不弹会员推广；主行动直接可用
02填写主题占位符给一个可照抄的完整示例，降低首次创作门槛
03提交时引导注册手机号 + 验证码；此前输入的主题与配置必须保留，不得丢失
04新用户赠点注册后明确告知"已赠送 X 点，可免费生成一份 8 页 PPT"
05首次生成后引导在完成态给出下一步：导出 PPTX / 存为模版 / 再做一份

关键原则：先给价值，再要身份。注册墙出现在用户"已经投入了创作成本"的那一刻（提交生成时），转化率远高于落地即弹窗。同时必须保证注册前后的表单状态不丢失——这是最容易导致新用户流失的技术细节。

一致性 · 可访问性 · 响应式

这三项决定了方案能否"落地之后不走样"。它们不是设计完成后的检查项，而是必须写进代码约束、在 CI 里可验证的规则。

11.1 一致性：三个机制

① Token 单一来源

全部颜色、间距、圆角、字号、动效只在 index.css 的 @theme 中定义一次，组件通过 CSS 变量引用。禁止在组件内写死十六进制色值——当前 home.css 里仍有 #8d76ff、#c8b9ff、#b8a1ff 等硬编码紫色，正是缺少这条约束的结果。

② 组件状态矩阵

每个组件必须定义默认 / 悬停 / 按下 / 焦点 / 禁用 / 加载 / 错误 / 空态共 8 种状态（见 8.6 表格）。评审时逐格验收，未定义即视为缺陷。

③ 命名与结构约定

类名沿用 celano-{区块}-{元素} 前缀体系（现有代码已具备，应保留）；页面级容器统一为 celano-{page}-app / celano-{page}-main，让样式作用域可预测。

一致性 ≠ 所有页面长得一样

一致性指的是相同的语言，而非相同的留白。首页可以有大字号衬线标题和 96px 的区块间距，管理后台可以有 12px 行高紧凑表格——但它们使用同一套中性阶、同一套圆角阶、同一套强调阶梯、同一套动效曲线。判断标准是：用户能不能仅凭视觉就判断"这是同一个产品"。

设计理由与可用性改进建议

最后回答"为什么这样设计"，以及"接下来按什么顺序改"。

六条核心设计理由

1为什么是"黑白为骨、彩色为标点"，而不是全彩或纯黑白

全彩的问题不用解释；纯黑白的问题在于它把"当前状态"的表达手段压到了只剩明度——选中的页、当前导航项、键盘焦点，三者只能靠深浅微差区分，长时间使用必然丢失位置感。而解法不是加一套彩色主题，而是加5% 的、职责被严格限定的点缀色。
骨架仍然是黑白：14 级中性阶给足层级空间，强调阶梯让"点哪里"由填充度回答，状态形态语言让"到哪了"由边框样式回答。彩色只补最后一件事——"你现在在哪"。补齐之后，黑白反而比全彩更耐看：它不会在长时间使用后产生审美疲劳，也不会与用户自己生成的 PPT 画面（往往色彩丰富）抢注意力。

2为什么是双主题，而不是统一改成浅色或深色

产品有两类截然不同的界面：创作场（首页、生成器、工作台、画布——需要沉浸、需要让画面成为主角，暗色更合适）与文档场（个人中心、消耗记录、管理后台——需要长时间阅读文字与表格，浅色更合适）。强行统一会让其中一方受损。双主题的代价只是 token 需要定义两套值，而这个代价在 token 体系建立后是一次性的。

3为什么把"成本"从弹窗里拿出来

点数制产品的最大信任风险是"我不知道会花多少"。当前设计把成本藏在提交后的确认弹窗里，意味着用户在配置页无法做出理性决策——他不知道把 6 页改成 12 页、把 2K 换成 4K 到底多花多少，只能反复试。成本条常驻之后，配置行为从"猜"变成"算"，同时弹窗的打断次数也自然下降（小额操作不再需要确认）。

4为什么把"失败与退款"当成一等公民来设计

AI 生成必然有失败率，这是技术事实。但产品是预扣费模式，失败时用户感知到的是"钱被拿走了但没拿到东西"。后端已经实现了退款逻辑，界面却完全没有表达——这是一个纯粹的信息传递缺口，修复成本极低，但对信任度的收益极高。设计上把它做成失败卡片的固定组成部分（原因 + 已退回 + 重试），而不是一条会被错过的 Toast。

5为什么在无彩色体系里，动效是必需品而不是装饰

彩色界面里，颜色承担了"什么变了"的大部分传达工作——按钮变绿表示成功、变红表示失败、变灰表示禁用。放弃颜色之后，这部分职责必须有人接手，动效就是那个接手者：状态切换的交叉淡入、进度条的平滑推进、点数扣除的回弹确认、失败卡片的虚线晃动——它们替代了原本由色相完成的语义传达。
这也是"高级感"最直接的来源。同样一个黑白界面，动效做对了就显得精密、可控、有分量；没有动效或做得随意，就立刻退回"未完成的线框图"观感。所以第 07 章的动效规范不是可选项，而是这套黑白方案能否成立的前提。

6为什么彩色必须被"限权"，而不是被"喜欢"

加彩色最容易翻车的地方不是选错色，而是让颜色到处跑：主按钮染个色、标题染个色、卡片加个彩色顶边、图表再来一套配色……三次之后，界面就从"克制"变成了"热闹"。
本方案给每个颜色分配了互不重叠的语境——澜青只做交互状态、朱砂只做不可逆操作、涨跌只做数值。三者从不在同一视觉单元里出现，所以用户在任何一个局部画面里，最多只会看到一种彩色。
颜色的克制不是审美偏好，而是可用性要求：颜色越少，每一种颜色的含义越确定，用户判断得越快。这也是"高级感"和"花哨"之间真正的分界线——不是用了什么颜色，而是颜色承担了多少职责。
